# Support

Use the channel that matches the kind of help you need.

## Bug reports

If Anura behaves unexpectedly, first check the
[README troubleshooting guide](README.md#troubleshooting) and search
[existing issues](https://github.com/D3M-Sudo/Anura/issues).

If the problem has not already been reported, open a
[bug report](https://github.com/D3M-Sudo/Anura/issues/new?template=bug_report.yml).
Include the Anura version, installation method, desktop/session type, steps to
reproduce and relevant logs. Remove personal information, extracted text,
tokens and other sensitive data before sharing diagnostic output.

## Feature requests

For a proposed feature or change, search existing
[issues](https://github.com/D3M-Sudo/Anura/issues) first, then use the
[feature request template](https://github.com/D3M-Sudo/Anura/issues/new?template=feature_request.yml).
Describe the use case and the problem to solve; implementation proposals are
welcome but are not required.

## Security vulnerabilities

Do not report security vulnerabilities in public issues. Use
[GitHub Security Advisories](https://github.com/D3M-Sudo/Anura/security/advisories/new)
for private vulnerability reports. See [SECURITY.md](SECURITY.md) for the
project's security policy and data-flow information.

## Contributions and translations

- Read [CONTRIBUTING.md](CONTRIBUTING.md) before preparing a code change.
- Read [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for participation standards.
- Anura translations are coordinated through
  [Weblate](https://hosted.weblate.org/engage/anura/).

## Support expectations

Anura is maintained as an open-source project. Support is provided on a
best-effort basis; there is no guaranteed response time or service-level
agreement. Please keep requests focused, provide reproducible information and
be respectful of maintainers' time.
